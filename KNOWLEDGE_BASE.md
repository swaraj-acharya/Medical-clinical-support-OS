# Knowledge base

## Files

| File | Role |
|---|---|
| `data/master-medical-knowledge.json` | **The** canonical, normalised knowledge layer read by the app (~2.4 MB). Built, never hand-edited. |
| `data/source-registry.json` | Registry of all 76 sources (level, licence, integration, status). Generated by `scripts/build-knowledge-base/source_registry.py`. |
| `data/validation-report.json` | Output of the last build/validate: counts, errors, warnings, provenance coverage, stale sources, data-quality notes. |
| `data/curated/*.json` | Hand-curated inputs, every entity with `sources[]` and `verification`: symptoms (61, incl. romanised Hindi synonyms), body systems, red-flag rules (31) and checklist (10), allopathy (6 clinical contexts, 7 guidelines, 11 recommendations, 18 medicines, 13 interaction rules, 17 history conditions), drug-class lexicon, Ayurveda bridge (30 classical terms, dosha/agni/ama rules, safety notes), homeopathy (evidence, regulatory, 23 toxic-source flags, rubric hints, case-taking questions). |
| `data/processed/ayurveda/*.json` | Importer output from the Amidha Ayurveda CC BY 4.0 datasets: 360 herbs, 176 formulations (175 after de-duplication), 162 principles. |
| `data/processed/homeopathy/publicum.pack.json.gz` | Full Repertorium Publicum via OOREP: 74,667 rubrics, 2,432 remedies, 735,566 rubric–remedy grades (GPL-3.0). |
| `data/processed/homeopathy/boericke.pack.json.gz` | Boericke's *Pocket Manual of Homoeopathic Materia Medica* (1906), 688 chapters. |
| `data/processed/allopathy/` | Optional verification outputs: `openfda-labels.json`, `rxnorm-verification.json` (network importers), `atc-user-supplied.json` (user licence). Empty in this build — see limits. |

## Provenance and verification

Every clinical entity carries `sources[]` (`sourceId` from the registry, reference, URL, version, last verified) and a
`verification` status:

- `imported-from-source` — machine-imported from a bundled dataset (Ayurveda, homeopathy).
- `curated-pending-verification` — hand-curated from the cited source, **not yet verified** (all allopathic drug facts,
  red-flag encodings, bridges). 159 entities in v1.0.0.
- `curated-verified` — set automatically for a drug only when both the openFDA label check and the RxNav RXCUI check
  succeed; clinical sign-off is still required.
- `metadata-only` — citation without content.

The validator requires 100 % of clinical entities to have at least one source that exists in the registry.

## Build, validate, update

```bash
npm run knowledge:build        # deterministic: same inputs → same contentHash (generatedAt excluded)
npm run knowledge:validate     # exit 1 on any error; checks pack checksums
npm run knowledge:update       # stage → validate → diff (data/staging/update-report.json)
npm run knowledge:update -- --import --version 1.1.0 --promote   # re-import, then replace live file (backup kept)
```

`knowledge:update` never overwrites the live file without `--promote`, refuses to promote when validation fails, and
refuses when content changed but the version did not. Backups go to `data/backups/master-<version>-<hash>.json`.
After promoting, use **Data health → Reload knowledge base** (or restart). Every analysis and audit entry records the
version and content hash it used, so past results remain traceable.

## Validation checks

Duplicate IDs per collection; references between entities (contexts → symptoms/guidelines, recommendations → drugs,
interactions → drugs/classes, formulations → herbs, red-flag rules → symptoms/checklist, Ayurveda bridges → symptoms,
toxic-source flags → remedies); drug rules use only known patient-state tags; rubric hints exist in the repertory;
provenance coverage; registry references; stale sources (> 365 days since checked); unverified-status sources.

## Adding knowledge

1. Add or edit the curated JSON (keep `sources[]` and `verification`), or add an importer under `scripts/import/`
   that writes to `data/processed/…` with a manifest (input SHA-256, counts, licence).
2. Register any new source in `scripts/build-knowledge-base/source_registry.py`, run it, then `npm run docs:sources`.
3. `npm run knowledge:update` → review the diff → `--version x.y.z --promote`.
4. Add tests for new rules (`tests/unit/…`).

## Seed clinical scope (v1.0.0)

Allopathic contexts: migraine-type and tension-type headache features, dyspepsia/reflux, allergic rhinitis, acute
undifferentiated fever, common-cold URTI. Red-flag screening is broader (headache, pregnancy, chest pain, hypoxaemia,
consciousness, seizure, dehydration, paediatric danger signs, infant fever, anaphylaxis/angioedema, GI bleeding, sepsis
(qSOFA), NEWS2 red parameters, suicide risk, dengue warning signs, head injury, poisoning, snakebite, severe
hypertension). Ayurveda and homeopathy reference content covers the full imported datasets.
